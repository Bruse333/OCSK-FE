## 二、流程模式接入检索详情

### 2.1 核心数据流

```
检索结果列表（卡片）
  │
  ├─ 点击卡片 → 打开详情页
  │
  └─ 详情页中：
       │
       ├─ 记录无 flowUrl → 仅图文模式（当前已有功能）
       │
       └─ 记录有 flowUrl → 显示「图文/流程」Tab 切换
            │
            ├─ 图文模式：故障现象 + 排查步骤 + 图片附件 + 文档附件
            │
            └─ 流程模式（首次切换时懒加载）：
                 1. fetch(flowUrl) 下载 .flow.json 文件
                 2. parseFlow(text) 解析 + 校验
                 3. FlowRunner 组件播放引导式排查
                 4. 加载失败显示错误 + 重试按钮
```

### 2.2 API 接口依赖

| 接口 | 说明 | 关键字段 |
|---|---|---|
| `GET /trbsts` | 检索排查记录（分页+关键词） | 响应行含 `flowUrl`（流程文件 OSS 地址） |

### 2.3 小程序详情页改造要点

#### 2.3.1 数据结构扩展

详情页 `data` 中需要新增以下字段：

```javascript
data: {
  // ... 现有字段 ...

  // 流程模式相关
  detailTab: 'text',       // 'text' | 'flow'  图文/流程 Tab
  flowLoading: false,      // 流程文件下载中
  flowError: '',           // 流程文件下载/解析错误信息
  detailFlow: null,        // 解析后的流程对象
}
```

#### 2.3.2 Tab 切换逻辑

```javascript
// 打开详情时重置
openDetail(record) {
  // ... 现有逻辑 ...
  this.detailTab = 'text'
  this.detailFlow = null
  this.flowLoading = false
  this.flowError = ''
}

// 切换到流程模式：首次进入时懒加载
switchToFlowMode() {
  this.detailTab = 'flow'
  if (!this.detailFlow && !this.flowLoading && !this.flowError) {
    this.loadDetailFlow()
  }
}

// 下载并解析流程文件
async loadDetailFlow() {
  if (!this.currentDetail || !this.currentDetail.flowUrl) return
  this.flowLoading = true
  this.flowError = ''
  try {
    const res = await wx.request({
      url: this.currentDetail.flowUrl,
      responseType: 'text',
    })
    if (res.statusCode !== 200) throw new Error(`HTTP ${res.statusCode}`)
    const text = res.data
    const { flow, errors } = parseFlow(text) // 来自 flowSchema.js
    if (!flow) {
      this.flowError = errors[0] || '流程文件解析失败'
      return
    }
    this.detailFlow = flow
    if (errors.length > 0) {
      wx.showToast({ title: `已加载，${errors.length} 处自动修正`, icon: 'none' })
    }
  } catch (e) {
    this.flowError = '流程文件加载失败，请检查网络后重试'
  } finally {
    this.flowLoading = false
  }
}
```

#### 2.3.4 FlowRunner 组件移植

FlowRunner 是状态机驱动的引导式排查播放器，核心逻辑在 Web 端 `src/system/flow/FlowRunner.vue`。

**小程序版 FlowRunner 数据结构**：

```javascript
data: {
  currentId: null,       // 当前节点 id
  history: [],           // 历史栈 [{ nodeId, viaLabel }]
}

computed: {
  currentNode:       getNodeById(flow, currentId),
  typeLabel:         映射 { start:'开始', step:'步骤', decision:'判断', end:'结束' },
  displayTitle:      decision 节点显示 question，否则显示 label,
  displayDescription: 节点描述文字,
  photos:            currentNode.media.photos,
  docs:              currentNode.media.docs,
  pathLabels:        history.map(h => h.viaLabel),
}
```

**FlowRunner 核心方法**（与 Web 端完全一致）：

```javascript
import { getStartNode, getOutEdges, getNodeById } from './flowSchema'

methods: {
  restart() {
    const start = getStartNode(this.data.flow)
    this.setData({ currentId: start ? start.id : null, history: [] })
  },

  goNext() {
    const edges = getOutEdges(this.data.flow, this.data.currentId)
    if (edges.length === 0) {
      wx.showToast({ title: '流程数据异常：当前节点缺少下一步', icon: 'error' })
      return
    }
    const label = this.data.currentNode.type === 'start' ? '开始' : '完成'
    this.jumpTo(edges[0].target, label)
  },

  chooseOption(e) {
    const opt = e.currentTarget.dataset.opt
    const edges = getOutEdges(this.data.flow, this.data.currentId, opt.id)
    if (edges.length === 0) {
      wx.showToast({ title: '流程数据异常：该选项未配置后续步骤', icon: 'error' })
      return
    }
    this.jumpTo(edges[0].target, opt.label)
  },

  jumpTo(targetId, viaLabel) {
    const history = [...this.data.history, { nodeId: this.data.currentId, viaLabel }]
    this.setData({ currentId: targetId, history })
  },

  goBack() {
    if (this.data.history.length === 0) return
    const history = [...this.data.history]
    const prev = history.pop()
    this.setData({ currentId: prev.nodeId, history })
  },

  docName(url, index) {
    try {
      const seg = decodeURIComponent(url.split('/').pop() || '')
      return seg || `文档 ${index + 1}`
    } catch (e) {
      return `文档 ${index + 1}`
    }
  }
}
```

## 三、全局 UI 主题设计同步

### 3.1 设计哲学

**「深海蓝 · 工程感知识工具」**——以蓝色色阶为骨架，中性灰为支撑，海洋青为点缀。  
**核心原则**：主题色做"画框"（导航栏、品牌区），工作区保明亮（白卡片 + 浅灰底）。

### 3.2 四时段主题体系

| 时段 | 时间段 | 基调 |
|---|---|---|
| **夜晚** `night` | 19:00 ~ 05:00 | 深海军蓝 `#0B1B36` 主导，白色文字，青色光斑点缀，星星闪烁 |
| **清晨** `morning` | 05:00 ~ 11:00 | 亮蓝渐变 `#7DD3FC→#E0F2FE`，深灰文字，白云漂移 |
| **白日** `day` | 11:00 ~ 17:00 | 更亮蓝渐变 `#38BDF8→#E0F2FE`，深灰文字，白云漂移 |
| **傍晚** `dusk` | 17:00 ~ 19:00 | 紫橙渐变 `#1E1B4B→#4C1D95→#C2410C`，白色文字，落日呼吸+飞鸟 |

### 3.3 主题计算工具（theme.js，可直接复用）

```javascript
// theme.js - 时段主题工具（Web 与小程序共用）
export function getTimeTheme(date = new Date()) {
  const h = date.getHours()
  if (h >= 5 && h < 11) return 'morning'
  if (h >= 11 && h < 17) return 'day'
  if (h >= 17 && h < 19) return 'dusk'
  return 'night'
}

export function getGreeting(date = new Date()) {
  const h = date.getHours()
  if (h < 5) return '夜深了'
  if (h < 8) return '早上好'
  if (h < 11) return '上午好'
  if (h < 13) return '中午好'
  if (h < 17) return '下午好'
  if (h < 19) return '傍晚好'
  return '晚上好'
}

export function getGreetingIcon(theme) {
  if (theme === 'dusk') return 'sunset'
  if (theme === 'night') return 'moon'
  return 'sun'
}
```

### 3.4 主题切换机制

1. 小程序全局 `app.js` 在 `onLaunch` 时计算当前主题，存入 `globalData.theme`
2. 每个页面在 `onShow` 时从 `getApp().globalData.theme` 获取主题值
3. 页面根元素动态添加 class：`theme-{{theme}}`（morning/day/dusk/night）
4. 样式通过 `.theme-morning .xxx {}`、`.theme-night .xxx {}` 覆盖对应变量

```javascript
// app.js
import { getTimeTheme } from './utils/theme'

App({
  globalData: { theme: 'night' },
  onLaunch() {
    this.globalData.theme = getTimeTheme()
  },
  onShow() {
    // 每次从后台恢复时刷新主题（跨时段后自动切换）
    this.globalData.theme = getTimeTheme()
  }
})
```

```javascript
// 页面 onShow 中
Page({
  onShow() {
    this.setData({ theme: getApp().globalData.theme })
  }
})
```

### 5.8 小程序特有注意事项

| 事项 | 说明 |
|---|---|
| **rpx 换算** | 设计稿按 750px 宽度，1px = 2rpx。但颜色值无需换算 |
| **动画性能** | 小程序中避免大量同时运行的 CSS animation。星星控制在 12 个以内，动画时间错开 |
| **`prefers-reduced-motion`** | 小程序不支持该媒体查询，可通过 `wx.getSystemInfoSync().reduceMotion` 判断（如果支持），或统一降低动画密度 |
| **自定义导航栏高度** | 需计算状态栏高度 + 导航栏 44px（或 52px），确保内容不被遮挡 |
| **图片预览** | 用 `wx.previewImage` 替代 Web 端 `el-image` 预览 |
| **文档打开** | 用 `wx.downloadFile` + `wx.openDocument` 打开文档附件 |
| **网络请求** | `flowUrl` 是 OSS 公网地址，小程序需在后台配置 `downloadFile` 合法域名 |

## 六、注意事项与边界检查清单

### 6.1 流程模式边界处理

- [ ] `flowUrl` 为空或 `null` → 不显示 Tab，仅图文模式
- [ ] `fetch(flowUrl)` 失败 → 显示错误信息 + 「重试」按钮
- [ ] `parseFlow(text)` 返回 `flow === null` → 显示解析错误信息（`errors[0]`）
- [ ] `parseFlow` 有警告但 flow 可用 → 正常加载 + toast 提示"已自动修正"
- [ ] 流程数据异常（找不到开始节点等） → FlowRunner 内部显示错误 + 重新开始按钮
- [ ] 切换 Tab 时不重复下载：`detailFlow` 已加载则直接切换
- [ ] 关闭详情后重置 `detailTab='text'`、`detailFlow=null`

### 6.2 主题边界处理

- [ ] 跨时段时（如从 4:59 进入页面 → 5:00 后切换 Tab）需在 `onShow` 刷新主题
- [ ] 登录页不换肤（保持深蓝渐变，稳重）
- [ ] 系统设置页、检索页等所有业务页面的卡片底色统一为白色 + `--oc-card-border`
- [ ] 所有阴影用 `rgba(15, 23, 42, ...)`，禁止纯黑
- [ ] 所有颜色禁止硬编码，必须引用 Design Token
- [ ] 动画要有 `prefers-reduced-motion` 或小程序等效兜底

### 6.3 步骤序号样式（重要规范）

```
排查步骤序号统一使用：
  背景: --oc-blue-50 (#EFF6FF) 浅蓝底
  边框: 1.5px solid --oc-blue-600 (#2563EB) 蓝色描边
  文字: --oc-blue-700 (#1D4ED8) 深蓝字
  形状: 圆形 (border-radius: 50%)

❌ 禁止使用: 蓝色渐变实心圆
✅ 正确样式: 浅蓝底 + 蓝色描边圆环
```

### 6.4 文档附件命名

```
详情页文档附件统一显示: "文件 1"、"文件 2"、"文件 3"...
❌ 禁止显示: 原始文件名
```

### 6.6 flowSchema.js 移植注意

`src/utils/flowSchema.js` 是纯 JS 工具文件，不依赖任何框架，可直接复制到小程序项目使用。核心函数：

- `parseFlow(text, opts)` — 解析 JSON + 校验 + id 去重
- `validateFlow(flow, opts)` — 业务规则校验
- `getStartNode(flow)` — 获取开始节点
- `getOutEdges(flow, nodeId, optionId)` — 获取出边
- `getNodeById(flow, nodeId)` — 按 id 取节点
- `genId(prefix)` — 生成唯一 id
- `createNode(type, position)` — 创建节点
- `createFlow(overrides)` — 创建空流程

`parseFlow` 支持 `opts.regenerateIds` 参数，导入流程时重生成 id 防冲突。
